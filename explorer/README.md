# Psilocin human-neuron transcriptomic atlas

Static Observable Framework companion for the archived analysis. It displays frozen gene, pathway and sensitivity results and does not fit models or calculate new inferential statistics in the browser.

```bash
npm ci
npm test
npm run build
python3 -m http.server 4173 --directory dist
```

All runtime assets and scientific display data are local. Exploring archived results requires no third-party requests. Gene and protein context uses dated same-origin snapshots by default; live provider refresh is explicit. 3D coordinates load only for a chosen structure. A frozen build is also retained in the repository-level `site/` directory.

The build prepares deterministic pathway-display coordinates for each evidence tier from the archived atlas, recording its SHA-256. Display coordinates are reproducible and do not change scientific inputs; optional node repositioning uses copies of the prepared coordinates. Native Framework7 autocomplete reuses normalized search indexes, and bounded cohort caches retain immutable gene references across view changes.

## Pathway overlap

Pathways → Pathway overlap compares the 14 frozen gene sets using literal source symbols. The default uses full annotations; leading-edge mode uses the selected contrast's archived leading edges. Untestable sets have unavailable leading-edge overlaps, rather than zero. For each unordered pair, Jaccard similarity is the shared-symbol count divided by the union count. This is a descriptive annotation comparison, not an interaction network, co-expression analysis or new statistical test. Annotation overlap can reveal redundancy; it does not quantify independent biological support.

All sets remain visible, with no significance filter. The graph threshold hides connections only; the matrix, pairwise table and CSV preserve all pairs, including zero and unavailable values. Search highlights sets without changing overlap denominators. The deterministic D3 layout uses full annotations as a stable reference across contrasts and membership views; positions and distances have no biological meaning. Nodes have equal size and show archived NES on a fixed ±3.6 colour scale. P/S/E mark the original primary/secondary/exploratory families.

Select a connection or use the pair selector to inspect shared symbols and original gene estimates. CSV exports retain denominators and shared symbols; provenance JSON records view settings and scientific-input SHA-256 identities. SVG export contains the current layout, display threshold, membership mode and interpretation key. All computation uses local frozen display data; no external biological relationships are fetched.

## Comparative views

The optional Comparative views section links a gene cohort, visualization and original gene evidence. It includes cross-day coefficient scatterplots, transcriptome-wide volcano plots, approximate Wald interval panels, gene-effect beeswarms, categorical OXPHOS membership counts/parallel sets and a primary-pathway NES comparison. Selected gene identifiers persist across these alternatives and link to the established gene explorer and OXPHOS heatmap. No model is refitted; original gene FDR and pathway correction families remain unchanged.

Scatterplots compare Day 1/common-control and Day 3/common-control coefficients descriptively. Shared controls and unresolved control-harvest assignments prevent interpreting them as treatment-specific temporal trajectories. Volcano coordinates use the selected contrast's archived coefficient and gene FDR. Missing FDR values are omitted; numerical zero and transformed values exceeding 50 are capped at −log₁₀ FDR 50 and marked by triangles. Original values and censoring flags are retained in CSV. Effect-axis limits are explicit, and counts distinguish missing estimates from points outside the display window.

Interval panels use the unshrunken coefficient ±1.96 × its original standard error. At most 40 genes are plotted; complete eligible rows remain in exports. Default ordering is alphabetical; ordering by functional assignment, coefficient or standard error is explicit. Beeswarm offsets are graphical collision avoidance, not additional observations; dense placements that overlap are counted. Gene identifiers and numerical region selection provide accessible alternatives to pointer selection.

OXPHOS membership partitions the 113-gene leading-edge union into 6 Day-1-only, 89 shared and 18 Day-3-only genes. Counts and parallel sets use the same project functional display assignments. Ribbons encode categorical intersections, not temporal transitions or biological flux. The chord alternative under Pathway overlap is limited to six selected sets: equal angular sectors identify sets, and ribbon endpoints encode shared-symbol counts using one angular scale. Shared genes may contribute to multiple pairwise ribbons. Exact counts and denominators remain available through the pair selector, table and matrix.

PNG/SVG, selected-gene CSV, complete displayed-data CSV and provenance JSON exports preserve analysis context and scientific-input SHA-256 identifiers. URL selections are limited to 500 identifiers; larger selections remain available during the session and in exports, with a visible notice. No new statistical tests, interaction network or causal interpretation is introduced.


## Optional public gene context

Each gene-evidence panel opens a dedicated full-page Framework7 public-information sheet, with separate Gene annotation, Protein features and 3D structures tabs. The lookup strips only the archived Ensembl ID version for the API request and requires an exact stable ID, human species and Gene object response. Symbols are never used to infer an external identity. It displays the provider description, biotype, assembly, coordinates, strand, current gene version, original archived ID, retrieval time in UTC and the exact source URL. A changed version is explicitly flagged; current coordinates are not attributed to the archived annotation.

Before an explicitly requested live-provider connection, a Framework7 confirmation offers optional connection details naming providers, identifiers and requested data; cancellation makes no provider request. An unchecked “Remember my choice” option stores approval locally for the exact provider set across genes and visits; otherwise each new information session asks again. Changing that set or clearing browser storage requires confirmation again. Requests are user-triggered, credential-free and time-limited. Identical lookups share a bounded session cache; failed requests remain retryable. Unavailable or retired IDs do not imply missing expression or a null result. Provider text is rendered as text, never HTML. No external annotation changes the frozen gene symbols, memberships, estimates, multiple-testing families or scientific exports. Saved snapshot context is available offline; live refresh needs a connection. General gene annotation does not establish function, activity or a psilocin response in these cultures.

Provider references: [Ensembl ID lookup](https://rest.ensembl.org/documentation/info/lookup) and [data-use terms](https://www.ensembl.org/info/about/legal/disclaimer.html). Provider descriptions can contain source attributions; these are retained verbatim in the displayed record.

Protein visuals use a separate, dated UniProt snapshot (or explicit live lookup) restricted to human entries with an exact Ensembl GeneId cross-reference. Reviewed records are listed first; unreviewed products are disclosed separately. Each accession is labelled, with current gene cross-reference versions and UniProt entry/sequence versions. Matching a gene does not establish the protein isoform expressed in these cultures. Domain/site tracks use Observable Plot and retain exact inclusive UniProt residue positions and evidence codes; uncertain boundaries are omitted, and a maximum of 60 exact-position features is shown. The full provider record remains linked. InterPro links provide additional domain-family context.

PDB references retain UniProt's method, resolution and chain-coverage metadata. Selecting the 3D structures tab automatically opens an available bundled model (or the explicitly previewed model), with its accession and source displayed; alternatives remain explicit choices. The on-demand local 3Dmol.js 2.5.5 viewer displays deposited coordinates, which may include partners, fragments and engineered sequences; sequence-rainbow colouring is not confidence. AlphaFold models are offered only when the returned accession, human taxonomy, full canonical sequence and full-length coverage match the chosen UniProt entry. Models are labelled predicted; their pLDDT colours describe local model confidence, not experimental support, inter-domain orientation or cellular function. Missing structures are not evidence of absent protein or function. Exact provider URLs, retrieval times and model versions accompany the context. Public protein-context JSON exports are separate from archived analysis exports and use the existing download confirmation.

The approximately 0.55 MB molecular runtime loads only when opening a specific structure, with included runtime licences. One WebGL structure is active at a time; closing, replacing or leaving the view releases its observers and graphics context. Provider requests omit credentials, have time and size limits, and do not change frozen analysis inputs or statistical results. See the [UniProt API](https://www.uniprot.org/help/api_queries), [AlphaFold API](https://alphafold.ebi.ac.uk/api-docs), [RCSB PDB](https://www.rcsb.org/) and [3Dmol.js](https://3dmol.org/).

## Offline installation and molecular snapshots

The sidebar's **Install app** entry offers a native installation prompt when available, otherwise browser-specific instructions. Offline preparation is separate from browser installation: the research package includes every archived analysis and plot, gene search, available Ensembl annotations, compact reviewed OXPHOS protein records and structure previews. The larger protein/coordinate library is an explicit optional download. The installer displays measured decoded storage sizes; compressed transfer sizes can differ. Browser storage can be cleared or evicted.

Preparation verifies byte lengths and SHA-256 for every saved file, then starts the app in a cache-only frame and opens eight research sections before reporting success in Framework7. Existing installed packages update with content-hash reuse; a new worker activates only after its staged packages verify. Failed updates retain the previous complete package. The interface refreshes when idle, preserving the URL selection, and reports success after the new startup check. Optional molecular downloads remain optional and separate from the core package.

Public annotations are dated same-origin snapshots, not new experiment measurements. Ensembl stable identifiers are matched exactly; unavailable or retired records remain unavailable. UniProt records require an exact human Ensembl GeneId cross-reference. The full mapped protein snapshot and representative OXPHOS PDB/AlphaFold coordinate library load locally on demand, or from the optional offline package. Live refresh is an explicit, consent-protected action. External provider pages and models outside the bundled library need internet.

Snapshot maintenance is explicit: `scripts/snapshot-public-context.py` retrieves annotations into a maintainer-selected temporary directory; `scripts/snapshot-structures.py` adds representative OXPHOS coordinates. They are not build steps. `scripts/prepare-structure-previews.mjs` renders small local WebP previews using the pinned 3Dmol.js runtime. `public-context/index.json` and `previews.json` retain source URLs, retrieval times, hashes, licence assignments and coverage limitations. The 112 OXPHOS previews prefer exact canonical-sequence AlphaFold models, otherwise verified UniProt-mapped PDB chains; absence of a preview does not establish absence of protein or structure. The 113th gene has no bundled model. Dense plots remain text-only.
